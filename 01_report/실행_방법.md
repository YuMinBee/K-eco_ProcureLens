# 실행 방법

## 1. 대시보드 열기

`02_dashboard/procurement_decision_dashboard.html` 파일을 브라우저에서 열면 된다.

현재 대시보드에는 아래 품목이 포함되어 있다.

- `4710160801` 유기응집제
- `4111331901` 기타수질분석기
- `4016150601` 여과장치
- `4710160802` 무기응집제
- `4710169801` 수처리용여과재
- `4015150501` 정량펌프
- `4010160101` 송풍기
- `4111250101` 유량계
- `4015151301` 수중펌프
- `4014169401` 제수밸브

## 2. 전체 파이프라인 재실행

제출본은 `06_submission` 폴더만 제출하는 구성이므로, 대시보드 확인은 위 HTML 파일로 바로 가능하다.

전체 파이프라인 재실행은 원천 데이터와 API 키가 있는 환경에서 `06_submission` 폴더를 기준으로 실행한다.

```bash
python 03_code/run_procurement_dashboard_pipeline.py --top-per-item 50
```

기본 설정(`--ai-mode auto`)에서는 표준화된 학습 데이터가 저장된 HGB 모델보다 최신이면 자동 재학습하고, 그렇지 않으면 현재 후보업체만 예측한다. 과거 학습 데이터 범위나 모델 파라미터를 명시적으로 다시 반영하려면 아래처럼 재학습을 강제한다.

`score_hgb_supplier_candidates.py`는 전체 파이프라인 실행 중 `02_processed/후보업체_목록.csv`와 표준화 데이터가 생성된 이후 실행되는 내부 예측 단계이다. 제출본에서 결과만 확인할 경우 `04_outputs/model_outputs/HGB_후보업체_AI예측점수.csv`를 확인하면 된다.

```bash
python 03_code/run_procurement_dashboard_pipeline.py --ai-mode train --top-per-item 50
```

## 3. 새 물품 추가

제출본에 포함된 확인용 산출물은 `04_outputs/`에 저장되어 있다.

다만 파이프라인을 재실행하면 새로 생성되는 후보 목록, feature, AI 예측 결과, 대시보드 입력 목록은 `02_processed/`에 생성된다. `02_processed/`는 실행 산출물 폴더이며 GitHub 제출본에는 포함하지 않는다.

새 물품은 재실행 기준 `02_processed/대시보드_물품목록.csv`에 누적된다. 기존 물품을 다시 입력할 필요 없이 새 물품만 넣으면 된다.

```bash
python 03_code/run_procurement_dashboard_pipeline.py --item 4710169801:수처리용여과재 --top-per-item 50
```

## 4. 일회성 실행

누적 목록을 쓰지 않고 이번 입력만으로 실행하려면 다음 옵션을 사용한다.

```bash
python 03_code/run_procurement_dashboard_pipeline.py --item 4710160802:무기응집제 --top-per-item 50 --no-remember-items
```

## 5. 주기 갱신

일 단위 또는 시간 단위 갱신이 필요하면 scheduler를 사용한다.

```bash
python 03_code/schedule_procurement_updates.py --daily-at 02:00 -- --top-per-item 50
```
